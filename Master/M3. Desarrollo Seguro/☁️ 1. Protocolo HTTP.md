Como conocemos, dentro del protocolo TCP/IP existen diversas capas, dentro de la **capa de aplicación,** la cual es la cuarta en TCP/IP y la septima en el **OSI (Open System Interconnection),** encontramos diversos protocolos, entre ellos los tres más importantes son **HTTP, SMTP y FTP.**

**El protocolo HTTP** es el estándar para el uso en web, es el más usado en los servicios web que envían XML o JSON como estructura de datos, por lo que es un protocolo del **nivel de aplicación** que se utiliza para la **transferencia de información entre sistemas de forma clara y rápida.** Fue creado por <u><b>World Wide Web</b></u> en 1990 y sus especificaciones concretas están recogidas en **distintas RFC.** Las más importantes son **RFC 1945 y RFC 2616.**

Su funcionamiento se basa en **peticiones y respuestas,** donde un cliente **establece una conexión con el servidor,** realizando el envío de **una petición** en forma de <b><u>método, una URI y una versión de protocolo,</b></u> seguido de <b><u>los modificadores de la petición, la información sobre el cliente y un posible contenido al final.</b></u>

**El servidor** responde de forma similar con una **línea de estado** que incluye <b><u> la versión del protocolo y un código que indica el éxito o el error de la solicitud, seguida de la información del servidor en forma de mensaje MIME y un posible contenido.</u></b>

**Por lo que, en resumen:**

Para navegar por la web, el proceso comienza cuando introduces una URL o haces clic en un enlace. El navegador descodifica esa dirección para identificar el protocolo, el dominio y el objeto solicitado, estableciendo entonces una conexión **TCP/IP** con el servidor. Una vez conectados, el cliente envía una petición HTTP usando métodos como **GET** (para recoger datos), **POST** (para enviar información), **PUT** (para enviar objetos) o **HEAD** (para solicitar características del documento). Finalmente, el servidor devuelve una respuesta con un código de estado y la información solicitada, cerrándose la conexión a menos que se utilice el modo _keep alive_ para mantenerla abierta.

# 🔢 1.2 Codificación de la información

**MIME** (_Multipurpose Internet Mail Extensions_) es el estándar que permite al navegador y al servidor entender qué tipo de archivo se está transfiriendo. Originalmente creado para enviar adjuntos en correos electrónicos, hoy es fundamental en la web para que, al recibir un recurso, tu dispositivo sepa si debe tratarlo como una imagen, un vídeo, un documento HTML o un archivo PDF. Básicamente, funciona como una "etiqueta" que acompaña a la información para asegurar que se abra con la aplicación o el formato correcto.

Por otro lado, **IANA** (_Internet Assigned Numbers Authority_) es la entidad global encargada de supervisar la asignación de identificadores únicos en Internet, incluyendo precisamente la lista oficial de tipos MIME. Su función es mantener el orden y la estandarización para que todos los sistemas del mundo hablen el mismo idioma técnico; ellos gestionan desde las direcciones IP y los números de puerto hasta los protocolos, asegurando que no existan conflictos y que la comunicación digital sea fluida y universal.

**HTTP** se codifica siguientdo un método de codificación que puede ser: **7 bits, Quoted-printable o Base64.**

# 🦟 1.3 Vulnerabilidades en aplicaciones web

Es muy común que las aplicaciones estén compuestas por **tres niveles:** 
- **Nivel de presentación:** Formado por navegador web o motor de búsqueda
- **Nivel lógico:** Escrito en lenguaje de programación como **Java, C#, -NET, PHP, etc**
- **Nivel de almacenamiento:** Formado por una o varias bases de datos

Pero este modelo **no era seguro,** y se decidió incluir una nueva pieza, llamada **middleware,** o típicamente llamado **servidor de aplicación,** entre <b><u>servidor web y servidor de la base de datos.</u></b>

Es el **intermediario inteligente**. En lugar de que el servidor web (el que tú ves) acceda directamente a la base de datos, ahora tiene que pedírselo al middleware. Esto añade una capa de seguridad: si alguien hackea el servidor web, no tiene acceso inmediato a toda la información de la empresa, porque el middleware actúa como un **filtro o guardaespaldas**.

Aloja una interfaz de programación de aplicaciones o **API (Application Programming Interface)** para conseguir exponer la lógica y los procesos de negodico de forma que sean usados por los servidores web.

La API es la herramienta que usa el middleware para comunicarse. Piensa en ella como una **ventanilla de atención al cliente**: el servidor web llega a la ventanilla, hace una petición estructurada y el middleware le entrega solo lo que necesita. Esto permite "exponer la lógica de negocio" (es decir, las reglas de cómo funciona la aplicación) de forma ordenada y controlada.

# 🐽 1.4 Esnifado y codificación de cabeceras

Para analizar qué ocurre "bajo el capó" al navegar, se utilizan herramientas que interceptan las **cabeceras HTTP**, que son las etiquetas con información técnica que intercambian el cliente y el servidor. 

Principalmente existen dos tipos: 

- **Sniffers:** "escuchan" y capturan los datos que viajan por el cable o el aire. Se puede usar con **dos objetivos:**
	- Observar los datos que se envían y buscar un posible **CSRF (Cross-Site Request Forquery), XSS (Cross-Site Scripting), SQLi (SQL Injection)**
	- Para manipular las cabeceras enviadas y añadirle algún código malicioso que provoque en una aplicación vulnerable una respuesta que no era la que debía.

- **Proxies:** Se sitúan en medio de la conexión para permitirnos ver, frenar o incluso modificar esa información antes de que llegue a su destino. 

Estas funciones pueden venir integradas en extensiones del propio navegador o en potentes programas profesionales como **Burp Suite** u **OWASP ZAP**.

Además de estas herramientas de interceptación, existen métodos para hablar directamente con los servidores y manipular las cabeceras sin intermediarios. Programas de terminal como **Netcat**, **Ncat** o **Telnet** permiten escribir peticiones HTTP manualmente, lo que es muy útil para probar cómo responde un servidor ante datos específicos. Al usar versiones modernas como Ncat, que soportan cifrado SSL, es posible incluso saltarse ciertas restricciones de los **firewalls**, permitiendo un estudio mucho más profundo y flexible de la seguridad de las comunicaciones.
