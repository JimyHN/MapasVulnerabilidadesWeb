### **Codificación**

La codificación (o codificación de salida) consiste en traducir caracteres especiales potencialmente peligrosos a un formato equivalente pero inofensivo para el sistema que los recibe. Su objetivo es asegurar que el intérprete de destino (como un navegador) trate los datos como texto plano y no como código ejecutable. **Es crucial para detener los ataques XSS.**

En .NET se usa la biblioteca **Anti-Cross Site Scripting**
En PHP, en Zend Framework 2 (ZF2), se puede usar **Zend-escaper**

Una manera de codificación de caracteres es Unicode, que permite **almacenar caracteres con múltiples bytes**

- **Ejemplo HTML:** El símbolo `<` se convierte en `&lt;` para que el navegador lo dibuje en pantalla en lugar de abrir una etiqueta.
    
- **Ejemplo URLs:** Un espacio en blanco se convierte en `%20` para que la dirección web sea válida y no se rompa el enlace.

### **Escapar**

Escapar consiste en añadir un carácter especial de control justo antes de un carácter conflictivo para avisar al sistema de que debe ignorar su función lógica habitual. De esta manera, se evita que el programa malinterprete un símbolo de sintaxis como si fuera el final de una instrucción o un comando.

- **Ejemplo en Código:** Si quieres incluir comillas dentro de un texto, escribes `\"` para que el sistema entienda que es parte del mensaje y no el cierre de la frase.
    
- **Ejemplo en Rutas:** En muchos sistemas, para usar un espacio en un nombre de archivo, se antepone una barra `\` para que el terminal no piense que el nombre ha terminado.

### Validación

- **Validación de listas negras o blacklisting:** <u>Intenta comprobar que los datos dados no incluyen contenido malo conocido,</u> por ejemplo, una pagina web puede bloquear la entrada que contenga el texto exacto **"script"** para evitar el XSS.
- **Validación de listas blancas:** <u>Intenta comprobar que un dato determinado cumple con ciertas reglas.</u>

Cuando se construye un _software_ seguro, la lista blanca es el enfoque mínimo recomendado. Las listas negras son propensas a errores, pueden ser evadidas con varias técnicas y pueden resultar peligrosas cuando se depende de ellas por sí mismas.

Aunque las listas negras pueden sortearse, a menudo también pueden ser útiles para ayudar a detectar ataques obvios. Así, mientras que las listas blancas ayudan a limitar la superficie de ataque y a asegurar que los datos tienen la validez sintáctica y semántica adecuada, las listas negras ayudan a detectar y detener los ataques obvios.

Por seguridad, la validación de datos de entrada debe hacerse **siempre en el lado del servidor.** La validación del lado del cliente puede ser útil, pero realizarla solo ahí no garantiza tener una buena política de validaciones de datos dentro de la aplicación, ya que estas pueden ser fácilmente evadidas. 

Esto hace que la validación del lado del servidor sea aún más fundamental para la seguridad. En conclusión, las validaciones de datos deben hacerse en ambos lados, pero con especial atención en el lado del servidor.

### Identidad digital

Representación única de un usuario (u otro sujeto) cuando participa en una transacción en linea

Dentro de los niveles establecidos por **NIST 800-63b** tenemos tres niveles de garantía de autenticación conocidos por las siglas **AAL:**
- **Nivel 1 de AAL:** Contraseñas
- **Nivel 2 de AAL:** Autenticación multifactorial
	- Es un sistema que requiere **dos o más pruebas diferentes** para verificar tu identidad antes de dejarte entrar. Combina al menos dos de estas categorías: algo que sabes (clave), algo que tienes (móvil) o algo que eres (huella).
- **Nivel 3 de AAL:** Autenticación basada en criptografía
	- Es el nivel más robusto, donde no se envían claves "legibles" por la red. Se basa en **algo que tienes** (como un chip físico) que utiliza algoritmos matemáticos complejos para demostrar quién eres sin revelar tu clave secreta.

### Controles de acceso

El control de acceso (o autorización) es el proceso de conceder o denegar solicitudes específicas de un usuario, programa o proceso.

**DAC:** Control de acceso discrecional; restringe el acceso a objetos basándose en la identidad del sujeto y su necesidad de conocer los datos. El propietario del objeto decide quién tiene permiso para acceder a él.

**MAC:** Control de acceso obligatorio; restringe el acceso según la sensibilidad de la información (etiquetas) y la autorización formal del usuario. Es el sistema el que impone la política de seguridad por encima de la voluntad del usuario.

**RBAC:** Control de acceso basado en roles; identifica las acciones permitidas según el rol asignado al usuario dentro de la organización en lugar de su identidad individual. Facilita la gestión al agrupar permisos por funciones laborales.

**ABAC:** Control de acceso basado en atributos; concede o deniega el acceso analizando características específicas (atributos) tanto del usuario como del objeto. Permite políticas muy granulares, como el horario de acceso o la ubicación desde la que se conecta.
