## 5.3.1 Petición HTTP típica

Este apartado explica que **la comunicación web es una transacción entre un cliente (navegador) y un servidor (servidor HTTP)**. El cliente inicia el proceso enviando una solicitud estructurada que el servidor debe procesar.

<font color="#FF5555">GET</font> <font color="#50FA7B">/</font> <font color="#BD93F9">HTTP/1.1</font>

<font color="#FFB86C">Host:</font> <font color="#F1FA8C">example.org</font>

La <font color="#FF5555">línea de petición (GET)</font> indica el método usado, mientras que la <font color="#50FA7B">URL relativa (/)</font> define el recurso y <font color="#BD93F9">HTTP/1.1</font> la versión del protocolo. El encabezado <font color="#FFB86C">Host</font> especifica el <font color="#F1FA8C">dominio</font> al que nos dirigimos, permitiendo que un mismo servidor gestione varios sitios web.

## 5.3.2 Reconstruir una petición HTTP

Aquí se muestra cómo PHP permite acceder a los datos de la petición original mediante el array global `$_SERVER`. Es útil para registrar logs o depurar qué información está enviando exactamente el navegador del usuario.

<font color="#BD93F9">$request</font> = "<font color="#FF5555">{$_SERVER['REQUEST_METHOD']}</font> ";

<font color="#BD93F9">$request</font> .= "<font color="#50FA7B">{$_SERVER['REQUEST_URI']}</font> ";

<font color="#BD93F9">$request</font> .= "<font color="#FFB86C">Host: {$_SERVER['HTTP_HOST']}</font>\r\n";

La variable <font color="#BD93F9">$request</font> concatena los valores del servidor; <font color="#FF5555">REQUEST_METHOD</font> obtiene el verbo (GET/POST), <font color="#50FA7B">REQUEST_URI</font> la ruta solicitada y <font color="#FFB86C">HTTP_HOST</font> el nombre del servidor. Se usan secuencias como `\r\n` para respetar los saltos de línea requeridos por el estándar HTTP.

## 5.3.3 Respuesta típica

Tras recibir la petición, el servidor devuelve una respuesta. Esta incluye metadatos (cabeceras) y el cuerpo del mensaje, que suele ser el código HTML que el navegador renderizará para el usuario final.

<font color="#BD93F9">HTTP/1.1 200 OK</font>

<font color="#FFB86C">Content-Type:</font> <font color="#F1FA8C">text/html</font>

<font color="#50FA7B"><img src="image.png" /></font>

El código <font color="#BD93F9">200 OK</font> confirma que la solicitud fue exitosa, y el <font color="#FFB86C">Content-Type</font> avisa que el contenido es <font color="#F1FA8C">HTML</font>. Si el navegador encuentra una etiqueta <font color="#50FA7B"><img></font>, entiende automáticamente que debe realizar una nueva petición para descargar ese recurso visual.

## 5.3.4 Ejemplo de solicitud de recurso

Finalmente, se detalla cómo el navegador actúa cuando necesita un recurso secundario (como una imagen). Realiza una nueva petición GET de forma automática, sin que el usuario tenga que intervenir manualmente.

<font color="#FF5555">GET</font> <font color="#50FA7B">/image.png</font> <font color="#BD93F9">HTTP/1.1</font>

<font color="#FFB86C">Accept:</font> <font color="#F1FA8C">image/png, image/jpeg</font>

En esta nueva petición, el método <font color="#FF5555">GET</font> apunta directamente al archivo <font color="#50FA7B">/image.png</font>. La cabecera <font color="#FFB86C">Accept</font> informa al servidor qué <font color="#F1FA8C">formatos de imagen</font> es capaz de procesar el navegador para asegurar la compatibilidad.

Por lo que, podemos crear el siguiente formulario

# 5.7 Sesiones

En la mayoría de los ataques de suplantación de sesiones, el atacante intenta obtener acceso a la sesión de otro usuario haciéndose pasar por él.

Para obtener dicho acceso se puede hacer de tres maneras
- **Predicción:** Intentar obtener o adivinar el identificador de sesión válido.
- **Captura:** Al transmitir los identificadores normalmente en **cookies** o como variables **GET,** los enfoques se centran en atacar esto, aunque es **más seguro cookies que GET.**
- **Fijación:** Si un mecanismo de sesión consiste nada más que en **session\_start(),** es vulnerable
