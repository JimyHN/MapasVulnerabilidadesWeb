
Los ataques más empleados en este campo son:
- SQLi
- XSS
- Perdida de autenticación y gestión de sesiones
- Archivos mal configurados en los servidores de aplicaciones

En .NET es especialmente crítica la **ejecución de archivos maliciosos** en los que un atacante puede introducir datos y código hostil para explotar vulnerabilidades de la aplicación o la inclusión y ejecución remota de ficheros, denominada **RCE** (_remote code execution_).

Un **_deface_** de una página web consiste en la manipulación por parte de un usuario malicioso de los recursos de la aplicación web original. Para ello, tendrá que haber accedido al sitio web modificando algunos ficheros.

El **repudio** consiste en llevar a cabo una transacción sin que exista una prueba fehaciente de quién ha sido el autor de dicha transacción.

Revelar información (_**disclosure**_) es el hecho de desvelar información confidencial. Puede ser voluntariamente (por desconocimiento de que se está revelando) o involuntariamente (robo).

Un ataque de denegación de servicio consiste en hacer deliberadamente que una aplicación consuma más recursos de los permitidos, por lo que se bloquea el sistema y, por lo tanto, se produce una pérdida de disponibilidad. El típico ejemplo es la sobrecarga de una aplicación web para que no pueda servir más recursos al resto de usuarios.

Un ataque de concesión o elevación de privilegios consiste en emplear cualquier medio disponible para obtener más permisos que los asignados por la aplicación web.

**Una _cookie_,** como ya se ha visto, es un método para poder guardar la información debido a que el protocolo HTTP carece de estados. No obstante, al ser enviadas directamente desde el servidor al navegador del usuario, y viceversa, son vulnerables a la suplantación u otros usos malintencionados.

Un atace **DOS** es un ataque de Denegacion de Permisos, donde un atacante podría comprometer la aplicación web para que no estuviera disponible simplemente manteniéndola demasiado ocupada o bloqueándola
# 6.1 Recomendaciones generales de seguridad

Según las guías ofrecidas por la propia compañía Microsoft en su sitio web **MSDN (Microsoft Develper Network)**

- Realizar copias de seguridad y almacenarlas en lugares seguros
- Mantener los servidores en lugares físicos seguros
- **Emplear siempre el sistema de ficheros NTFS, jamás FAT32**
- Proteger los servidores con contraseñas complejas
- Proteger los servidores ofrecidos por el IIS conforme a las recomendaciones oficiales ofrecidas en el Microsoft TechCenter de Seguridad
- Desactivas servicios no necesarios
- Cerrar puertos no usados
- Ejecutar un antivirus de forma periódica sobre todos los ficheros almacenados
- Ejecutar un firewall adecuado
- Instalar las ultimas versiones de seguridad de Microsoft y terceros
- Emplear y examinar registros de eventos
- Detectar actividades sospechosas

# 6.3 Contramedidas para la pérdida de autenticación

- **Empleo de funciones integradas:** Utilizar las herramientas de seguridad nativas del framework para evitar errores de programación y asegurar estándares actuales.
    
- **Control LoginView:** Componente que muestra distintas vistas (como enlaces o mensajes) según si el usuario está autenticado o no en la web.
    
- **No emplear cookieless:** Configurar la sesión para que use exclusivamente cookies, evitando que el identificador de sesión sea visible y vulnerable en la URL.
    
- **Tiempo máximo de expiración:** Definir un límite temporal de inactividad tras el cual la sesión se cierra automáticamente para proteger la cuenta del usuario.
    
- **Cifrado del contenido de la sesión:** Enmascarar los datos almacenados en las cookies de sesión para que no puedan ser leídos ni manipulados por terceros.
    
- **Evitar la función de autocompletar:** Desactivar la sugerencia automática de nombres de usuario en los formularios para impedir que se revelen cuentas usadas anteriormente.
    
- **Evitar el autoguardado de credenciales:** Impedir que el navegador almacene contraseñas automáticamente, reforzando la seguridad en equipos que no son de uso personal.
