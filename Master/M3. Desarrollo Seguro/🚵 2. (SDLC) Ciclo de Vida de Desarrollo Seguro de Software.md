El problema está en que hoy en día ña mayoria de procesos de desarrollo se llevan a cabo sin seguridad o incluyendola al final del propio proceso, esto supone un problema **económico, de recursos y de tiempo** si se detecta una vulnerabilidad en el entorno de producción, ya que <b><u>el coste de solucionarlo es mayor cuanto más tarde se detecta.</b></u>

Por lo que el trabajo del **Departamento de seguridad** es el de implementar la seguridad en <u><b>todas las etapas a lo largo del ciclo de vida del desarrollo de software (SDLC) hasta el final.</u></b>

En esta sección más adelante hablaremos del SDLC de Microsoft, conocido como **Microsoft SDL.**

# 2.1 Fases de un SDLC

El ciclo de vida de desarrollo de sistemas (SDLC) es una metodología estructurada que organiza el proceso de creación de software de manera metódica y deliberada. Su objetivo principal es guiar cada etapa de construcción mediante un enfoque iterativo que permite la mejora continua a través de un ciclo específico de actividades bien definidas.

Con la evolución tecnológica, la seguridad se ha vuelto un componente crítico que debe integrarse en cada una de estas fases. Esto da lugar al concepto de **S-SDLC** (Ciclo de Vida de Desarrollo de Software Seguro). Según la organización OWASP, este enfoque consiste en un conjunto de principios y buenas prácticas diseñados para detectar, prevenir y corregir vulnerabilidades desde el inicio, garantizando así aplicaciones robustas y resistentes ante posibles ataques maliciosos.

Un ejemplo destacado de esta metodología es el modelo propuesto por Microsoft (SDL), el cual organiza el desarrollo en las siguientes fases clave:

- **Formación y organización:** Establecimiento de directivas y capacitación del equipo.
- **Requisitos y diseño:** Definición de los parámetros de seguridad desde la planeación.
- **Implementación:** Desarrollo del código siguiendo estándares seguros.
- **Comprobación:** Pruebas de verificación para asegurar que el sistema cumple con los requisitos.
- **Lanzamiento y respuesta:** Despliegue del software y gestión de incidentes posteriores.

Finalmente, para medir la efectividad de estos procesos, el modelo de optimización del SDL establece cuatro niveles de madurez: **básico, estandarizado, avanzado y dinámico**. Estos niveles permiten a las organizaciones evaluar y escalar la calidad y seguridad de sus procedimientos de desarrollo de forma progresiva.

### 2.1.1 Seguridad en la fase de Análisis

En esta fase, se centra en **la toma de requisitos del software, sean funcionales o no,** lo que permite identificar **diversas características:**
- **Definición de la arquitectura de la aplicación:** ¿Será cliente/servidor o **desktop**?
- **Plataforma** (PC, móvil, tablet...)
- **Tipos de datos** confidenciales o públicos
- **Normativas y marcos regulatorios** que auditan el sistema (PCI-DSS, GDRP, EIOPA, etc)
- **Registros:** Acceso a recursos, uso de privilegios...
- **Roles necesarios:** Administrador, revisor, editor, invitado, usuario básico, etc
- **Permisos sobre los datos de cada rol:** lectura, escritura, ejecución, modificación, agregado...
- **Acciones que puede realizar cada rol:** Arrancar/detener servicios, cambiar config. del sistema...
- **Forma establecida de autenticación de contraseñas:** doble factor, tokens o biometria

### 2.1.2 Seguridad en la fase de Diseño

Muchas de las vulnerabilidades que presentan las aplicaciones web tienen origen en los errores que se pueaden cometer en el diseño, como por ejemplo:
- **Aplicación Home Banking (WEB):**
	- Al hacer una transferencia, se realizaba una petición que **incluía el número de cuenta,** el cual era manipulable desde la petición HTTP
- **Aplicación de Administración y Finanzas (Consola Unix):**
	- La aplicación utilizaba el nombre de usuario que estaba almacenado en una variable de entorno. Si se manipulaba el campo para **incluir una inyección,** se permitía la ejecución de una _shell_ o terminal.

### 2.1.4 Seguridad en la fase de codificación

Aquí es donde **se generará el código fuente de la aplicación con base en la arquitectura diseñada y cumpliendo con los requisitos establecidos.** La falta de controles de seguridad en esta etapa es la principal causa de las vulnerabilidades que pueden comprometer la aplicación o sus datos en los entornos de producción.

Existen vulnerabilidades mencionadas anteriormente como **CSRF, XSS, SQLi, Path traversal, Open redirect, Log forging o Hardcoded password o credentials.**

### 2.1.5 Seguridad en la fase de pruebas

En esta etapa se aplican varias pruebas como:

- **Prueba de seguridad funcional**
	- Valida las funcionalidades de seguridad de una aplicación implementada.
- **Pruebas de seguridad basadas en riesgo**
	- Se desprende del **threat modeling,** Genera casos de prueba sobre cada interfaz basada en **STRIDE.**
- **Pruebas con un cliente/server falso**
	- Se basa en diseñar un **cliente o servidor ad hoc** que permita realizar peticiones y respuestas erróneas.
- **Prueba de estrés (fuzzing)**
	- Llevar a una aplicación al **límite mediante una alta carga y petición.**
- **Prueba de mutación de datos**
	- Se prueba la aplicación mediante **el envío de datos mutados por sus interfaces.**

# 2.1.6 Seguridad en la fase de Despliegue

Corresponde con la **última etapa técnica del ciclo.** En ella se aplican prácticas de seguridad como el _hardening_ o bastionado de los servidores o sistemas de base, que comprende:

- **Desinstalación o deshabilitación de los servicios innecesarios.**
- **Cambiar los usuarios y contraseñas por defecto.**
- **Correcta configuración de intérpretes.**
- **Separación de los entornos (_dev, test, pre y pro_).**
- **Gestión de _releases_ y _patches o hot fix._**
- **Administración de implementación y mantenimiento.**
- **Firma del código fuente.**

# 3. SDLC-IT (Systems Development Life Cycle for Information Technologies)

Este ciclo no debe verse como un conjunto de elementos aislados, sino como un transcurso continuo de actividades en acción que pueden realizarse simultáneamente, repetirse o ser cíclicas. Su objetivo es transformar la construcción de sistemas en un proceso metódico y deliberado.

**Fases del Ciclo de Vida (SDLC)**

- **1. Identificación de problemas, oportunidades y objetivos:** Se define el propósito del proyecto y qué necesidades debe resolver.
    
- **2. Formación y concienciación:** Preparación y capacitación del equipo involucrado.
    
- **3. Requisitos funcionales y no funcionales:** Definición detallada de lo que el sistema debe hacer y cómo debe rendir.
    
- **4. Diseño de la solución:** Creación de la arquitectura y el esquema técnico del sistema.
    
- **5. Implementación:** Fase de construcción y codificación real del software.
    
- **6. Verificación y pruebas:** Evaluación rigurosa para detectar errores y confirmar que el sistema funciona correctamente.
    
- **7. Despliegue y entrega:** Instalación del sistema en el entorno final para el uso del cliente.
