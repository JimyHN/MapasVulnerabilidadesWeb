La auditoría o **penetration test de infraestructuras** engloba las diferentes fases que se ejecutan sobre los sistemas informáticos de una organización para identificar las debilidades que pueden acarrear un riesgo.

Dentro de estas fases se encuentran:
- Reconocimiento activo y pasivo
- Escaneo
- Explotación
- Escalada de privilegios

Existen dos tipos de auditorías, **pentest interno o pentest externo** y dentro de ellas, tres tipos: **caja blanca, caja negra o caja gris.**

# 🕒 2.3 Fases de la ejecución de las auditorías de Pentesting

## 💡 2.3.1 Reconocimiento

En esta fase, consiste en recoger toda la información del objetivo de forma activa y pasiva para estudiarla y encontrar los vectores de ataque.

Se utilizarán técnicas de inteligencia de fuentes abiertas (_open source intelligence_ -OSINT-).

Además, estas técnicas permiten obtener información del objetivo sin enviarle ningún paquete. 

**OSINT** es la forma de recolección de inteligencia que engloba encontrar, seleccionar y adquirir información de recursos públicos para ser analizada y producir inteligencia (información relevante).

### 👂 2.3.1.1 Reconocimiento pasivo o Footprinting

Consiste en recolectar <u>información pública</u> disponible en internet y otras fuentes. Es el proceso de recolección de información del objetivo que se pretende atacar usando información de dominio público. Esto incluye información obtenida en motores de búsqueda como Google, Bing o Whois.

Al tratarse de datos públicos, el objetivo del ataque no tiene forma de detectar que se están recopilando datos sobre él.

Con esta información, podemos obtener una visión general de la organización que se quiere atacar en la que se pueden exponer diferentes datos relativos, como <i> servicios publicados, aplicaciones, cuentas de correo electronico, empleados que trabajan en ella, procesos de selección de nuevos empleados, etc.</i>

#### 👤 2.3.1.1.3 Enumeración Whois

Es un servicio TCP, un tipo de base de datos y una herramienta muy útil para extraer información de una organización, como dominios, nombres de servidor, registrador, información de contacto...

Además permite la búsqueda inversa la cual proporciona la dirección IP.

**Es un framework de reconocimiento web escrito en Python que cuenta con módulos independientes y diferentes funciones.**

**Este framework permite, además, importar nuevos módulos.**

### ⚡ 2.3.1.2 Reconocimiento activo o Fingerprinting

Consiste en recolectar <u>información a través de la interacción con la organización.</u> una vez se ha recopilado la información necesaria en la fase anterior.

La recopilación de información activa puede ser detectada por el objetivo al ser un comportamiento malicioso o sospechoso.

Consiste en obtener información básica interactuando con los sistemas de la organización y viendo como responden. Como:
- mapear activamente la infraestructura de la red.
	- **mapear:** Identificar y catalogar los componentes reales de la red, es decir, **descubrir que dispositivos existen, cómo están conectados, qué servicios ofrecen y por donde se comunican.**
- Enumerar máquinas
- Analizar vulnerabilidades en un servicio abierto
- Buscar de manera activa servidores, archivos y directorios

#### 🌐 2.3.1.2.1 Enumeración DNS

Los servidores DNS ofrecen una serie de datos sobre **organización de servidores** que se encuentran disponibles de **forma pública,**
- direcciones IP
- nombres de servidores
- funcionalidad de estos
- etc.

Un servidor DNS normalmente divulgará información de DNS y de servidor de correo para el dominio sobre el que tiene autoridad. 

- Se puede usar el comando **host -t** para consultar información DNS de un dominio y descubrir servidores relacionados, como los de correo y los DNS principales.

Cada dominio debe ofrecer por defecto datos de sus servidores DNS y de correo; esto permite obtener hostnames y direcciones IP, e incluso automatizar el proceso con consultas repetidas.

Si se consulta un subdominio inexistente, el DNS responde con un error (NXDOMAIN). Esto permite comparar respuestas y detectar cuáles subdominios sí existen.

#### 💼 2.3.1.2.2 Enumeración SMB

**SMB, Server Message Block,** es un protocolo de red cuyo objetivo es compartir archivos, impresoras, etc. <u>Entre las máquinas pertenecientes a una misma red de ordenadores.</u>

El historial de seguridad de este protocolo ha sido deficiente durante más de una década debido a su compleja implementación y a su naturaleza abierta.

Las debilidades de este protocolo van desde la existencia de sesiones nulas de SMB no autenticadas, las cuales consistía en poder conectarse a **recursos SMB** <u>sin usuario ni contraseña</u>,  en Windows 2000 y XP hasta una gran cantidad de errores de SMB y vulnerabilidades a lo largo de los años. La más conocida y reciente es **EternalBlue**.

**EternalBlue:** es una vulnerabilidad crítica de SMBv1 explotada en 2017. Fue desarrollada como herramienta de espionaje por la NSA y luego filtrada. Aprovechaba un fallo de SMBv1 que permitía **ejecutar código malicioso remoto sin autenticación**.

#### 🧬 2.3.1.2.3 Escaneando el servicio NetBIOS

NetBIOS utiliza los puertos **139 y 445** y puede analizarse con **Nmap** o herramientas como **NBTscan** para detectar equipos, servicios compartidos y posibles recursos expuestos.

<b><i>root@kali:~# nmap -v -p 139,445 -oG smb.txt 10.10.10.1-254</i></b>
#### 🔐 2.3.1.2.4 Enumeración de sesiones NULL

Una sesión NULL es una conexión **no autenticada** a equipos Windows que puede revelar información sensible (usuarios, grupos, equipos, políticas, etc.). 

Esto era posible en **SMB1** por defecto y facilita ataques más avanzados. Herramientas como **Enum4linux, SmbClient, RPCClient, Net y Nmblookup** permiten esta enumeración, además de scripts de Nmap.

####  🔎 2.3.1.2.5 Enumeración SMTP

**Simple Mail Transfer Protocol,** es un protocolo de red utilizado para el intercambio de mensajes de correo electrónico.

Suele asociarse a otros protocolos como P0P3 o IMAP, <u>el SMTP se utiliza para <b>correo de salida</b> y los otros para <b>correo entrante.</b></u>

Algunos servidores de correo suelen estar mal configurados y mediante técnicas de enumeración es posible obtener información sobre el host objetivo.

SMTP suele disponer de <u><b>comandos</b></u> como **VRFY** o **EXPN,** que sirven para verificar los usuarios existentes en un servidor de correo.

#### 📥 2.3.1.2.6 Enumeración SNMP

**Simple Network Management Protocol,** es un protocolo basado en UDP que facilita el  intercambio de información entre dispositivos de una misma red.

Es un protocolo simple sin estado y susceptible a **IP spoofing** y **ataques de repetición.**

Además, los protocolos SNMP 1, 2 y 2c de uso común no ofrecen cifrado de tráfico, lo que significa que la información y las credenciales SNMP se pueden interceptar fácilmente a través de una red local.

## 📡 2.3.2 Escaneo

Una vez finalizada la fase de reconocimiento, se da paso a la fase de escaneo, aquí es donde se amplia la información de la que se dispone.

Normalmente el tipo de información que hay que recolectar en esta fase irá dirigida a tener una visión más amplia de:
- Infraestructura de la red
- SO desplegados
- Tipos de servicios que se proporcionan
- Versiones de estos servicios
- Posibles vulnerabilidades que puedan darse

# 📚 2.3.2.1 Tipos de escaneo

## 🔵 2.3.2.1.1 Escaneo / Descubrimiento de red

Este tipo de escaneo resulta de vital importancia a la hora de tener una visión más general del entorno objetivo, su direccionamiento IP y la arquitectura de sistemas que lo componen.

Cada entorno dispone de una estructura **totalmente distinta,** por eso es tan importante esta fase, ya que gracias a ella podremos adaptarnos a ese entorno específico y conseguir adaptar los siguientes escaneos al entorno de pruebas.

### 🟢 2.3.2.1.1.1 Descubrimiento de host mediante ICMP

El primer paso del escaneo es **descubrir cuántos hosts existen en un rango de red**, y aunque muchas técnicas de descubrimiento externo pueden usarse internamente, desde la red interna pueden aplicarse métodos adicionales específicos.

La técnica más común usa el protocolo **ICMP**, que envía mensajes de petición-respuesta para conocer el estado de un host y la calidad de la red. 

Con herramientas que emplean ICMP, se consultan direcciones o rangos de IP, obteniendo respuestas que permiten saber si el host está accesible o no.

<b><u>CONCEPTO IMPORTANTE:</b></u>

<u>Enviar un <b>ping</b></u> consiste en mandar un mensaje de tipo **ICMP Echo Request** a una dirección IP para comprobar si ese host está activo y disponible en la red. Si el equipo responde con un **ICMP Echo Reply**, significa que está encendido, accesible y conectado.

### 🔴 2.3.2.1.1.2 Descubrimiento de hosts mediante ARP

Esta técnica usa el protocolo **ARP**, que sirve para averiguar qué dirección física (MAC) corresponde a una dirección IP dentro de la red local. Para ello, el equipo envía un mensaje broadcast preguntando quién tiene una IP determinada, y el dispositivo que la tiene responde con su dirección MAC.

Como ARP funciona solo dentro de la red local, **esta técnica solo es útil en escaneos internos**. Además, como no depende de ICMP, **puede detectar dispositivos incluso si los pings están bloqueados.**

<h3 align="center">A. Descubrimiento de host con herramienta Arp-scan</h3>

Permite descubrimiento de equipos remotos mediante mensajes broadcast de tipo ARP Discovery e indicar la interfaz de red desde donde se quiere realizar el escaneo.

<i><u>La siguiente captura de pantalla muestra el escaneo de un rango IP clase C a través de Arp-scan.</u></i>

<div style="display: flex; justify-content: space-between; align-items: center;">
  <img src="arpscan.png" alt="Imagen 1" style="width: 100%; border-radius: 8px;">
</div>

en la sentencia de la imágen arp-scan 10.211.55.0/24 estamos reservando con /24 24 bits, ya que la direccion IP viene dada por 32 bits, 24 para red y 8 para hosts

Ejemplo: 

`192.168.1.0/24` es equivalente a la máscara:

`255.255.255.0`
<p align="center"><b>¿Qué rango abarca?</b></p>

Incluye todas las IP desde:

`192.168.1.1  hasta  192.168.1.254`

(lo que te permite escanear 254 posibles dispositivos)

<p align="center"><b>La razón por la que un rango /24 va solo del 1 al 254 es porque dentro de una red hay dos direcciones que no pueden asignarse a dispositivos:</b></p>

**1) La primera dirección → Dirección de red**

Corresponde a la identificación del propio segmento de red, no a un equipo.

Ejemplo en `192.168.1.0/24`:

`192.168.1.0  →  Dirección de red`

**2) La última dirección → Dirección de broadcast**

Se usa para enviar mensajes a todos los dispositivos de esa red al mismo tiempo.

Ejemplo:

`192.168.1.255  →  Dirección de broadcast`

<p align="center"><b>Entonces, ¿qué queda para los dispositivos?</b></p>

Todas las direcciones **entre la de red y la de broadcast**:

`192.168.1.1  al  192.168.1.254`

Eso nos da **254 direcciones posibles para equipos**, como PCs, móviles, cámaras, TVs, routers secundarios, etc.

<p align="center"><b>Resumen muy simple</b></p>

- `.0` → identifica la red
- `.255` → mensaje para todos
- `.1 – .254` → para dispositivos

`/24` solo indica cuánto de la IP pertenece a la **red**, y gracias a eso se calcula cuántas direcciones puedes escanear.

## ⚠️ 2.3.2.1.3 Escaneo / Búsqueda de vulnerabilidades

Aquí comprobamos si una determinada versión de un programa o servicio se encuentra afectada por alguna vulnerabilidad conocida.

Es fácil de comprobar una que disponemos anteriormente del escaneo de puertos, obteniendo los servicios y sus versiones que se encuentran prestando servicio

Se centrará la atención en el uso de la herramienta Nmap pero también se introducirán algunos ejemplos de otras herramientas, como **NC** y **Zenmap**.

Este último tipo de escaneo se centra en localizar posibles vulnerabilidades conocidas que se asocian a una determinada versión y tipo de servicio.

**DOS CONCEPTOS BÁSICOS E IMPORTANTES:**

Una **CVE** es una vulnerabilidad conocida que se encuentra registrada públicamente con un identificador único, lo que permite compartir información sobre ella de forma estándar.

Un **0-day** es una vulnerabilidad desconocida por el fabricante y sin parche disponible; puede ser usada en ataques antes de que exista una solución, lo que la hace especialmente peligrosa.

### 🧭 2.3.2.1.3.1 Nmap como escáner de vulnerabilidades

Nmap también puede utilizar la potencia de sus scripts NSE para actuar a modo de pequeño **escáner de vulnerabilidades.** 

Para ello, es posible usar los scripts incluidos en la categoría Vuln, los cuales identifican en el sistema remoto ciertas vulnerabilidades conocidas, basándose en el tipo y en la versión del protocolo que se encuentre detrás de ellos.

Cabe destacar que la mayoría de estos scripts no comprueban la existencia de la vulnerabilidad, de modo que conviene comprobar si la vulnerabilidad realmente existe o, por el contrario, es un falso positivo.

- De la misma manera, existe un proyecto llamado Vulscan, que consta de un script NSE que comprueba en una base de datos local que contiene vulnerabilidades de varias fuentes públicas (Exploit-DB, SecurityFocus, CVE, etc.).

- (<https://github.com/scipag/vulscan>)

- En caso de que la versión del protocolo o servicio se vea afectada por alguna vulnerabilidad conocida que se encuentre registrada en la base de datos, el script lo indicará.

- Para instalarlo se ha de clonar el proyecto de GitHub (<https://github.com/scipag/vulscan>) en la carpeta de scripts de Nmap. Una vez copiados los ficheros, se puede invocar su ejecución como si de otro script se tratase.

### ☢️ 2.3.2.1.3.2 Nessus

Nessus, con bastante diferencia, es la aplicación de escaneo de vulnerabilidades más conocida y utilizada. Actualmente existen dos versiones

- **Nessus Home:** válido únicamente para entorno personal. No se pueden escanear más de 16 hosts a la vez y no dispone de soporte de la herramienta ni de acceso a los módulos de _compliance_.
- **Nessus Professional:** válido en entornos profesionales. No dispone de limitaciones de escaneo e integra varios tipos de análisis de _compliance_, como PCI. Además, incluye soporte de la herramienta.

### 📑 2.3.2.1.3.2 Escáneres más específicos

Dentro de estos escáneres encontramos: **Sslscan, Qualys, Acunetix, Nikto, JoomScan, Cmscan, etc.**

#### 📜 2.3.2.1.3.2.1 Escáneres de protocolos

Escáneres enfocados a localizar vulnerabilidades segun la version o tipologia de los protocolos.

En esta categoría podrían englobarse herramientas cómo **Sslscan o Testssl,** que buscan vulnerabilidades conocidas en el tipo de protocolo **TLS o SSL,** utilizado para proteger las comunicaciones.

#### 📱 2.3.2.1.3.2.2 Escáneres de aplicaciones o frameworks

Se pueden englobar bastantes escáneres que tratan de localizar vulnerabilidades conocidas en _frameworks_ web tipo CMS, como **Joomla, Drupal, Wordpress, etc.**

En esta sección pueden encontrarse programas como **JoomScan, Wpscan, Droopscan, etc.**

#### 🌐 2.3.2.1.3.2.3 Escáneres de vulnerabilidades web

Escáneres más generalistas que tratan de descubrir vulnerabilidades en cualquier tipo de aplicación web. 

No se basan en localizar vulnerabilidades conocidas, sino en aplicar las técnicas necesarias para descubrir nuevas vulnerabilidades sobre estas.

Como escáneres más representativos de esta categoría están las aplicaciones de pago **Qualys Web-app y Acunetix.**

- Cve.cs
- Securityfocus.csv

## 🔐 2.3.2.2.1 Escaneo interno

Las pruebas desde la **red interna** se realizan dentro de alguno de sus segmentos, y los resultados dependen de la **zona donde se esté conectado**, ya que cada segmento puede tener distintos servicios y accesos.

En la red interna pueden encontrarse **servicios no visibles desde el perímetro**, como directorio activo, sistemas de autenticación por roles, facturación, videovigilancia o control de instalaciones, lo que permite analizar recursos más sensibles y específicos de la organización.

## 🔓 2.3.2.2.1 Escaneo externo

En este enfoque, las pruebas se realizan **desde fuera de la organización**, por lo que solo se puede analizar el **perímetro expuesto a internet**. 

Esto limita la visibilidad a los servicios publicados externamente, como correo, intranets o páginas web accesibles desde el exterior.

# 📝 Ejercicio práctico

localizamos ip de nuestra máquina que es 192.168.0.34, nos movemos dentro de la red 192.168.0 por lo que, realizaremos una busqueda tipo 0/24 que significa una busqueda de los 255 hosts disponibles dentro del rango .0 de nuestra red, si la ip fuese 192.168.1, estariamos en la red .1

192.168.X.Y

comprobar que en la Y, el /24 indica los bits reservados para la red, que significa **los primeros 24 bits de direccion que forman la mascara de red.** Esto equivale a 255.255.255.0, 255 en binario representa **8 bits activados**
- 8 bits + 8 bits + 8 bits = 24 bits
- 255 + 255 + 255 + 0 = 255.255.255.0

Entonces… ¿qué rango abarca 192.168.0.0/24?

|Tipo de dirección|Rango|
|---|---|
|Dirección de red|192.168.0.0|
|Primera IP usable|192.168.0.1|
|Última IP usable|192.168.0.254|
|Broadcast|192.168.0.255|
Por ello, al hacer **sudo netdiscover -i enp0s3 -r 192.168.0.0/24, nos saldra, primeramente 192.168.0.1 que hace referencia a nuestro ruter, luego 192.168.0.34 que es nuestra direccion de nuestra maquina en este caso, y el resto son diferentes dispositivos conectados a la red.**

creamos una maquina victima que será nuestra kali de ip: 192.168.0.39

Desde nuestra parrot comprobamos aquellas maquinas conectadas a nuestra red, con sudo netdiscover -i enp0s3 (nuestro este de ip) -r 192.168.0.0/24 y encontramos a la victima

Dentro de la victima abrimos dos puertos y los comprobamos desde la atacante con nmap -sT 192.168.0.34 y nos salen el 22 y el 8000 abiertos

Luego podemos hacer lo mismo con XMAS haciendo **Nmap -Pn ip -sX**

además con XMAS podemos meterlo en un archivo que podemos catear con: **Nmap -Pn ip -sX  -oX resultado.**

usamos para ver los puertos activos: **Nmap -Pn -sV ip.**

y para la versión de la maquina que nos sale una Linux: **Nmap -Pn -A ip.**
