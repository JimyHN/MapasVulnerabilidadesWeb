
# 📚 4.1 Phising

**Definición:** <i> Consiste en el fraude en el que se realiza una suplantación de un <b>sitio web</b> o <b>aplicación</b> con el objetivo de obtener, de forma ilícita o mediante engaño, cualquier tipo de información sensible o confidencial de un usuario. </i> **Es de creación muy sencilla** 

**Principales objetivos:**
- Entidades bancarias
- Portales de mensajeria (Outlook, Gmail, Hotmail, etc.)
- Portales de metodos de pago
- Comercios electrónicos (amazon, Ebay, Paypal, etc.)

# 📥 4.2 Vectores de entrada y distribución

Hoy en día, debido a las mejoras de seguridad constantes, estos han disminuido en gran medida, pero caben destacar dos: 
## 📮 4.2.1 Malspam

Consiste en el spameo de miles de correos electrónicos que usan *phising*, se emplea como **gancho** cabeceras que llamen la atención al usuario, como **"URGENTE, transferencia recibida, acceso bloqueado temporalmente, activación de datos..."**

Estas campañas suelen tener correos **bien estructurados,** y **relacionados** con la entidad o sitio web que se tratan de suplantar, además de normalmente utilizar técnicas de spoofing.

La esperanza de vida de estas campañas masivas de phising no supera las 24 horas, además de que, puede ser **contraproducente,** ya que, al no tener en cuenta a quien envías los correos, se pueden enviar correos phising a:
- Personas que denuncian el caso
- Empleados de compañias que detectan suplantaciones
- A los propios de ciberseguridad

**Postfix permanecerá en escucha por el puerto 587, como protocolo de envío usa DMTP `(simple mail transfer protocol)` y como requisito de autorización y autenticación para poder enviar correos MSA `(mail submission agent)`**

- Instalamos **Postfix:** 
	- *sudo apt-get install postfix*

- Instalamos **Dovecot,** un MDA que usa el protocolo IMAP `(Intenet Message Access Protocol)`:
	- *sudo apt-get install dovecot*

- Instalamos **Procmail,** un MDA que realiza los filtros requeridos y llama al script para parsear cada correo que llega:
	- *sudo apt-get install procmail*

## 📣 4.2.3 Distribución por anuncios

Por otro lado, los atacantes pueden usar otros métodos para la distribución de phising, como la de utilizar las **herramientas de pago** de los propios buscadores (Google, Bing, Yahoo, etc.) para mostrar **anuncios** que aparentan ser legítimos pero que, tras hacer click, redirigen al usuario al sitio web de phising.

Esta técnica suele tener mucho éxito pero su detección es prácticamente inmediata, su esperanza de vida no pasa las 3 horas.

Para entenderlo hace falta entender los **Google Ads,** el cual es un servicio de Google que se utiliza para ofrecer publicidad patrocinada, basándose en el PCC `(Pago Por Click)` por el que el anunciante indica un ratio de coste por click, el que mayor ratio posea aparecerá mostrado en primera fila, por tanto, si un atacante incluye un anuncio de coste 1€, y acceden 10.000 usuarios, le supondrá un cargo de 10.000€.

desde la posición del **analista,** para detectar estas campañas de forma proactiva basta con crear un script que, a través de la herramienta de diagnostico de Google Ad, monitorice los anuncios mostrados para las búsquedas de las palabras clave que interesen.

## 🧍 4.2.4 Distribución a través de la víctima

Otro método usado que tiene un altísimo porcentaje de éxito es el de, una vez se ha realizado una primera distribución teniendo mínimamente un usuario infectado como éxito, el cual introduce las credenciales, el propio atacante, a través de un bot o script, accede de manera ilícita a la cuenta del correo comprometido y distribuye la campaña de phising a todos sus contactos, obteniendo un plus de credibilidad. 

*Ejemplo: Cualquier parásito que infecta otros seres vivos para introducir sus larvas y se alimenten.*

## 💬 4.4.5 Smishing

<div style="border-radius:10px; padding:12px; box-sizing:border-box;">
  <p style="margin:0 0 10px 0;">Como dice su nombre <b>(SMS - phishing)</b> se trata de un phising que se distribuye mediante <b>mensajes de texto</b> a <b><u>teléfonos móviles.</b></u></p>
  <p style="margin:0 0 10px 0">Este mensaje contiene el enlace al sitio web donde se encuentra el phising.</p>
  <p style="margin:0 0 10px 0">Cada vez gana más fuerza y se vuelve más famoso, ya que en la actualidad, el uso de los teléfonos móviles para cualquier cosa está en aumento.</p>
  <p style="margin:0 0 10px 0;">
  Este tipo de phishing supone un <b>mayor coste de producción</b> al atacante:<br>
  • El número desde el que se distribuye puede detectarse rápidamente como fraudulento por las compañías telefónicas.<br>
  • La cantidad de SMS enviados debe ser menor que la de correos, porque las operadoras podrían bloquear el envío.<br>
  • Es más complejo obtener una lista de teléfonos de posibles destinatarios que una de correos.
</p>

# 🧬 4.6 Análisis de tráfico

Es importante entender y realizar correctamente un análisis básico de tráfico para poder avanzar, o entender el significado de ciertos términos

## 🧾4.6.1 Términos
### 4.6.1.1 🔗 Referer

Muestra la **dirección URL** de donde proviene el usuario que accede al sitio web.

**Referer:** http://en.wikipedia.org/wiki/Main_Page

---

### 4.6.1.2 🧠 User–agent

Muestra información del usuario, como el sistema operativo, el navegador utilizado, etc.

**User-Agent:** Mozilla/5.0 (Windows; U; Windows NT 5.1; en-US) AppleWebKit/525.19 (KHTML, like Gecko) Chrome/1.0.154.53 Safari/525.19.

---

### 4.6.1.3 📂 Content–type

Muestra el tipo de contenido de la petición.

**Content-Type:** text/html; charset=UTF-8.

---

### 4.6.1.4 🌐 Request URL

Muestra la URL solicitada.

**Request URL:** http://google.es.

---

### 4.6.1.5 🪛 Request method

Muestra el método utilizado para la petición.

**Request Method:** GET.

---

### 4.6.1.6 🧱 Status code

Muestra el estado del sitio web solicitado.

**Status Code:** 301 Moved Permanently.

---

### 4.6.1.7 📏 Content–length

Muestra el tamaño del contenido de la petición.

**Content-Length:** 218.
